# Task 12-d 采购建议单代理 - 工作记录

## 任务
库存预警 → 一键生成采购建议单（PR-YYYYMM-XXX）→ 模拟到货入库（既有调整库存）闭环；GET/POST /api/purchase-requests + ledger.tsx 盲板库存页签采购建议区 + MANAGER/ADMIN 通知广播。

## 改动文件
1. `src/app/api/purchase-requests/route.ts`（新建）
   - POST：校验 items 非空(≤50)/suggestQty≥1 整数/inventoryId 存在/去重 → 编号 PR-YYYYMM-XXX（currentYm 当月自增，从 PURCHASE note 内存推导最大序号）→ createMany ChangeRecord(action='PURCHASE', blindCode='spec/type/material', fromStatus='LOW_STOCK', toStatus='ORDERED', note='采购建议单 PR-xxx：建议补货 N 件', operator=__actorName, workCode/location=null) → pushNotifications 广播 MANAGER+ADMIN（ALERT，title='采购建议单 {code}'，content 含项数+合计件数，bizType=INVENTORY/bizCode=code/linkModule=ledger/linkTab=inventory）→ 返回 {code,totalQty,operator,createdAt,items}
   - GET：action='PURCHASE' AND note startsWith '采购建议单 PR-' 倒序 50 条，内存按 note 正则分组 → [{code,createdAt,operator,items:[{blindCode,spec,type,material,suggestQty,quantity,minQuantity}],totalQty}]（quantity/minQuantity 按 spec/type/material 关联当前库存快照）
   - 不新增 Prisma 模型/新表
2. `src/components/bp/ledger.tsx`（盲板库存页签增量，plates/records 页签未动）
   - 类型 PurchaseItem/PurchaseGroup；EXTRA_STATUS_LABEL={LOW_STOCK:'低库存',ORDERED:'已下单'} 仅作 statusLabel 兜底（未改共享 bp-types.ts）
   - 库存表新增「选择」列：表头全选 Checkbox（支持 indeterminate 半选）+ 低库存行 Checkbox（aria-label='选择 {spec} {type}'）；TableSkeleton cols 8→9、空态 colSpan 8→9
   - 选中>0 时表头上方 amber 浮条「已选 N 项低库存物料 · 建议数量自动填缺口（可改）」+ 取消选择 + 生成采购建议单按钮
   - 生成 Dialog：明细表（规格/类型/当前库存/最低库存/建议补货量 Input number 默认=gap 可改）+ 实时合计 + 确认提交（逐项校验≥1）
   - 提交成功：toast（编号/项数/合计/已通知）→ 清空选择 → 自动展开历史卡 → 并行刷新库存+历史
   - 「采购建议历史」Collapsible 折叠卡：单数 Badge / 导出建议单 CSV / 刷新 / Skeleton / 空态；每组=编号+明细 N 项合计 X 件 Badge+时间+操作人+六列明细小表

## 关键决策
- 采用「每项一条 PURCHASE ChangeRecord」方案（备选为单条聚合+仅通知）：变动记录逐规格可追溯，状态列直观显示「低库存→已下单」，与到货后「调整库存」正数入库形成两阶段留痕；通知广播两方案都需要，故取留痕更丰富者
- 编号用 currentYm 思路（PR-202609-XXX），序号从当月既有建议单 note 内存推导
- spec/type/material 以数据库 InventoryItem 为准（防前端脏数据）
